# STOCK EDGE INTELLIGENCE

日本株のテクニカル・財務・公開記事を比較するHTMLアプリです。総合スコアの根拠・充足度を表示し、買い取引の数量と想定損失を計算できます。

スコアは候補比較用の仮説モデルで、勝率・期待収益率や利益を保証するものではありません。収益性のバックテストは未実施です。

## Market Voiceを読む

一覧の手前に「ブログの気付きを、調査候補へ」を表示します。公開本文を取得できた記事とRSSの範囲を区別し、銘柄ごとに企業価値、業績、株主還元、変化のきっかけ、反対材料、前提条件を整理します。原文の短い根拠とリンクを残し、未抽出を「リスクなし」と扱いません。複数銘柄の記事、年度・金額の誤ったコード化、同じ抜粋の転載による合意数の水増しを避けます。これは規則による部分的な抽出であり、記事全体の意味を理解したAI評価ではありません。

「株価・財務を更新して照合」で、記事の論点と現在のRSI・20日変化、取得済み年次財務を並べます。年次の実績と記事の将来予想は対象期間が違う場合があるため、機械的に正誤判定しません。日経225以外も、記事中にコードと社名が明示された銘柄は調査候補として扱います。株価は返却された銘柄コードと通貨を検証します。自動株価取得は東証の `.T` ルートを使用しており、地方市場など取得できない市場は未確認のままです。取引所の全上場銘柄リストとの照合は行っていません。

「仮説を追跡する」では、自分の理由・撤回条件・状態・監視価格・見直す日と初回の根拠を端末内に保存します。後で編集しても初回の抜粋と保存時株価は書き換えません。保存時に未取得だった株価も未取得のまま残します。価格条件の到達、見直し期限、保存後に公表された記事を見直し候補に表示します。記事の投稿時株価からのリターン、著者の勝率、予想利益は算出しません。

調査候補の順序は見直すべき作業の順です。新記事・期限・価格条件・著者間の異なる見方等を使い、売買の有利さを採点しません。総合スコアに本文の抽出語を機械的に加点することもありません。自動更新が有効な間は保存した仮説の株価を30分間隔で、1巡2銘柄まで確認します。全体の通信上限と非表示・オフライン休止、失敗時の再試行間隔を共有します。

本文取得は登録した元ブログの同じHTTPSホスト・著者パスに限定し、robots.txtを確認します。記事本文の領域を特定できたものだけ解析し、本文全体は保存・再配信しません。1巡16記事まで、同時3接続、同じ記事の本文は通常36時間再取得しません。ログイン・有料領域・取得拒否の回避は行わず、取得不可はRSSのまま扱います。

ホーム上部の「市場の声を読む」、または銘柄詳細の **MARKET VOICE → 記事・意見を読む** から記事一覧へ進めます。銘柄詳細では、3軸のすぐ下にその銘柄の見出し・媒体・公表日・原記事リンクを表示します。

- 強気・弱気・混在／中立の件数は、直近30日以内の採点対象の意見を集計します。ニュース材料とは分けます。
- 記事一覧では、銘柄・媒体・キーワード、専門家関連記事／意見／ニュース、見出しの方向、期間で絞り込めます。24件ずつ追加表示しますが、検索は保存済み全記事が対象です。
- 「この銘柄を優先取得」は株価の取得済み・未取得を問わず使用できます。ほかの収集中なら、その完了後に優先します。
- 未取得、取得中、記事なし、通信失敗、古い記事のみを区別して表示します。閲覧中に記事が増えたときは「新しい情報を表示」から内容を更新でき、勝手に読んでいる記事を入れ替えません。
- 見出しの自動判定であり、専門家の本人確認や記事本文の精読ではありません。「強気を維持しつつ目標株価を引下げ」などは混在・中立として整理します。記事内の目標株価は原文で確認してください。

`voice-view.js` は一覧・鮮度・状態の純粋な処理、`voice-ui.js` はHTMLに内包した表示処理のソースです。

## Wi-Fiで継続更新

各画面の「更新モード」で設定できます。

- **自動（Wi-Fi優先）**：Wi-Fi・有線LANと判定できる場合は常時更新。判定不能なら標準速度で継続します。`effectiveType: 4g` だけではWi-Fiとは判定しません。
- **常時更新（Wi-Fi用）**：判別できないブラウザでWi-Fi利用中に選択してください。全体最大6通信、株価最大4並列、Voice最大3検索並列で巡回します。
- **省通信**：全体最大2通信。携帯回線・低速回線・ブラウザの省データ設定も優先して抑制します。
- **自動更新を停止**：自動巡回を停止します。手動取得は利用できます。

株価は24銘柄ずつ（標準は12銘柄）、Voiceは16銘柄ずつ（標準は8銘柄）処理し、長い固定休止を挟まず継続します。Voiceは銘柄別に取得履歴を持ち、上位銘柄ばかりを再取得しません。常時更新でも最新データを無限に取り直さず、株価は概ね平日9〜16時に5分、それ以外は1時間、Voiceは10分を再取得の目安とします。取引所休日や配信元の実際の更新頻度までは判定しません。

画面非表示・オフライン時には通信を中断し、新規取得を止めます。戻ると再開します。失敗時は15秒から最大10分へ待機を延長し、429/503の応答ではRetry-Afterを尊重します。画面全体の更新は5秒以上空け、入力欄の操作中は差し替えません。記事・財務データの反復解析も抑制しています。

回線種別の自動判別には対応しないブラウザがあります：[NetworkInformation.type](https://developer.mozilla.org/en-US/docs/Web/API/NetworkInformation/type)。速度は取得先の応答や制限に左右されます。GitHub Pagesの外部取得制約は引き続き適用されます。

`refresh-runtime.js` と `verify-refresh.cjs` に通信制御とそのテストを分離し、HTMLにも同じ処理を内包しています。

## GitHub Pagesで公開

1. このフォルダーの公開用ファイルをGitHubの公開リポジトリの `main` ブランチにアップロードします。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. **Actions → Publish GitHub Pages → Run workflow** を実行します。
4. 完了後、Settings → Pages に表示される公開URLへアクセスします。

ワークフローはテストに成功した場合のみ、`public/index.html` と `.nojekyll` をサイトへ公開します。mainへの更新時も自動デプロイします。

`index.html` をブラウザで直接開くこともできます。

## データ取得の制約

- GitHub Pagesは静的ホスティングのため、同梱の `server.cjs` は実行されません。公開版のRSS・株価・財務の取得は、元のブラウザ側取得経路と外部中継の稼働状態・CORS制限に依存します。
- 安定した公開用データ収集には、別途バックエンドまたは利用条件に沿った定期収集基盤が必要です。今回の公開設定には含みません。
- 専門家情報は公開記事の見出し・概要からのキーワード分類です。本人確認や有料レポート本文の取得には対応しません。原記事・公式開示を確認してください。
- ウォッチ等は各閲覧者のブラウザに保存されます。端末間では共有されず、ファイル版・ローカル版・公開版の保存領域も別です。

## ローカル起動

Node.js 22以降で次を実行します。追加パッケージは不要です。

```sh
npm start
```

http://127.0.0.1:8765 を開きます。Windowsでは `起動.cmd` も使用できます。ローカル版だけは、Google News/Bing Newsに限定したRSS中継を利用します。

# 個人投資家のブログ

Market Voiceに13フィード・12人の個人ブログを登録しています。元サイトのRSS/Atom/RDFから、公開された見出し・日付・リンクと短い配信概要だけを収集します。本文は公開部分の短い根拠抽出に限って参照し、全文や有料部分は配信しません。銘柄分析、運用記録、投資考察を探せます。「情報源を確認・表示設定」で元ブログ・RSS・取得状況を確認し、表示を切り替えられます。

ブログの一覧は著者ごとに分散して表示します。同じ著者のブログとnoteはスコア上も同一の情報源として扱います。日経225の会社名または明示された銘柄コードが見出しで確認できた場合だけ、その銘柄に関連付けます。小型株・市場全体・銘柄が曖昧な記事は閲覧用として掲載し、個別銘柄の採点から除外します。掲載や自動分類は著者の成績・記事の正確性の検証を意味しません。

GitHub Actionsの公開処理で、通常2時間ごとに3接続まででブログRSSを収集します。GitHubの実行待ちや配信元の事情で遅れることがあります。端末は配信済みJSONを1回の通信で同期し、通常30分は再取得しません。ボタンによる更新は配信済みデータの再同期です。元ブログへの即時巡回ではありません。取得失敗時は前回の記事を維持し、古い記事は「すべての期間」で確認できます。HTML単体にも配信時点のデータを内蔵しています。

情報源は `community-sources.json`、収集処理は `collect-community.py` で管理します。`npm run build` はPython 3（標準ライブラリのみ）でブログを収集してHTMLとJSONを生成します。オフラインビルドでは `STOCK_EDGE_SKIP_FEEDS=1` で保存データを使用できます。
