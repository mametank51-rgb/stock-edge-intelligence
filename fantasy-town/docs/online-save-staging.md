# オンライン保存機能の検証

## 公開状況

2026-11-01: 保存機能を公開中の `ashenvale-room` へ反映済み。旧サーバーからの切り替えは、旧オンラインデータが消える可能性を了承いただいたうえで実施。旧メモリ内のデータを新しい保存先へ自動移行することはできない。

## 保存されるもの

- プレイヤーID、名前、種族、職業、外見、位置・方向。歩行中は最大5秒間隔、退出・プロフィール変更・移動ポイント使用時などにも保存する。
- 各プレイヤーのバッグ、スタック、装備、耐久、品質と製作経験。
- 取引掲示板の出品と預かり品、プレイヤー双方の代金・品物。持ち物と出品物を同一の保存データとして記録する。
- 消滅期限内の地面アイテム。期限切れの品物は再起動時に復元しない。地面アイテムの数が上限500に達すると、それ以上のドロップや破棄は受け付けない。

名前などはオンライン接続後、サーバーに保存した値を優先して画面に復元する。端末内のオフラインデータとは共有しない。端末のサイトデータを削除すると、現在の方式では同じプレイヤーIDで復帰できない。

## 保存されないもの・制約

HP・MP・死亡状態、モンスターの状態、採取地点の再使用時間、チャット履歴は再起動後に初期化される。位置の自動保存は5秒間隔のため、突然の障害では最後の移動の一部が戻る場合がある。

プレイヤーIDはアカウント認証ではない。IDを知る第三者によるなりすましを防止できず、個人情報や価値のあるデータを扱う本番運用には適さない。現段階では知人同士の試用向け。正式運用には本人認証、データ移行・復旧、管理機能と負荷対策が必要。

旧サーバーのインメモリ状態を新しいデータベースへ自動移行する仕組みはない。旧サーバーは保存自体を行っていないため、更新時に未保存データが失われる可能性がある。オフラインのブラウザ保存データは別管理。

## 実装

`worker/src/RoomPersistence.ts` はSQLite内の単一レコードにルーム状態を保存し、読み込み時に形式・アイテム・所有重複・装備・出品・バージョンを検査する。不正な保存データは自動で上書きせずエラーにする。

`TownRoom` はアイテム変更、採取、製作、出品・購入、攻撃時の耐久変化、入退室、プロフィール変更、一定間隔の移動で保存する。保存に失敗した場合は成功を通知せず接続を閉じ、保存不能のまま処理を続行しない。サーバー起動時にデータを読み込み、再入室した本人に `PLAYER_RESTORE` を送る。

## 実施した検証

- `npm run build`、Workerの型チェック・dry-run、`npm test` の11スイートが成功。
- 隔離したローカルWorkerの実停止・再起動後、名前・位置・装備・出品物を復元。ブラウザ画面でも名前・位置・装備の復元を確認。
- ２ブラウザの入室・移動・チャット・再接続と、２接続の戦闘・取得・取引をローカルWorkerで確認。
- メモリを使ったテストで製作経験・地面アイテム・売買後の双方の所持品、重複データ拒否、保存失敗時の停止を確認。
- 公開中ゲームとは別の一時Cloudflare Workerにて２接続、装備・出品の保存、Workerを別バージョンに更新した後の復元を確認。一時Workerはテスト終了後に削除。
- 公開Workerの隔離ルームで２接続、装備・出品の保存、再接続後の復元を確認。公開Worker自体の再起動は検証目的では行っていない。

`tests/check-durable-restart.cjs` はsetup・verifyの２段階で動作し、同じ `--persist-to` を指定したローカルWorkerを間に再起動して使用する。`TEST_WS_URL` を指定すると隔離ルームの公開Workerにも使える。`tests/check-restored-browser.cjs` は再起動後のローカルWorkerとViteを使うブラウザ確認。
