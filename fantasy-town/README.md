# Ashenvale — 灰樹の町

ブラウザ向けトップダウン RPG の探索デモです。町の背景はユーザー提供の画像を使用し、操作可能な人物はコード生成の仮素材を重ねています。オンライン同期は別途 Worker を起動・設定すると利用できます。

## 起動と公開

```sh
npm install
npm run dev
npm run build
npm run preview
```

`dist/` を GitHub Pages 等へ公開できます。Vite の `base: './'` はリポジトリのサブパスにも対応します。このワークスペースの既存 Pages ワークフローは別の株アプリ用です。ゲームを公開する場合は、その公開先を上書きしないよう別リポジトリまたは既存サイトのサブディレクトリに `dist/` を配置してください。

## 操作

- WASD / 矢印キーで移動、Shift を押して走る。ホイールでズーム。
- タッチ端末は左下のスティックで移動。横画面推奨。
- NPC に近づいて E、または NPC をクリック／タップして会話。遠い場合は近づくよう表示します。Esc または × で閉じます。
- 敵をクリック／タップ、または Tab で近い敵を選択し、Space または「攻撃」で攻撃します。Esc、死亡、距離で解除されます。Warrior 等は近接、Archer は矢、Mage は MP を消費する魔法です。
- I または「持ち物」でバッグ、C または「人物」で装備画面を開きます。品物を選んで装備・使用・地面に置く操作ができます。装備画面のスロットを選ぶと解除できます。落ちた品物は近づいて F、またはクリック／タップで拾います。
- 町の「若木」「鉱脈」「釣り場」「薬草」「繊維草」に近づいてクリック／タップすると素材を採取できます。右下の「手しごと」からレシピと必要素材を確認し、製作できます。
- オンライン時は「取引」からバッグの品物を出品・購入できます。価格は古い硬貨で指定し、スタックは全量を出品します。硬貨はゴブリンなどから入手できます。出品は取り下げ可能です。
- 右下の「人物」で種族、職業、外見を即時変更できます。能力差や保存はありません。
- Enter でチャット入力、Enter または送信ボタンで発言します。プレイヤー名は「人物」で変更でき、端末に保存されます。別の端末または別のブラウザプロファイルで異なる ID を使ってください。
- F3 でデバッグ表示、表示中に F4 でプレイヤーと障害物の衝突切替。NPC およびワールド端の衝突は維持されます。

## 主な構造

- `state/GameState.ts`: 表示に依存しない `PlayerState`。ID、位置、方向、移動状態、外見、HP/MP。
- `characters/definitions.ts`: 種族、職業、外見と将来の装備レイヤーの型。
- `characters/CharacterAssetRegistry.ts`: 外見・方向・動作ごとの仮フレームを生成し、テクスチャを再利用。
- `characters/CharacterView.ts`: 名前、影、選択リング、Y 座標順、Idle / Walk / Run の表示とフレーム更新。
- `entities/LocalPlayer.ts` と `input/MovementInput.ts`: プレイヤー入力と物理移動。タッチ側の走行入力を追加可能。
- `data/npcs.ts`、`npc/types.ts`、`npc/Npc.ts`: NPC 定義と状態、表示、待機・巡回・徘徊。地形との衝突は Arcade Physics で処理し、移動先に到達できない場合は待機に戻ります。
- `scenes/TownScene.ts`: ワールド、各システム、入力を接続。`ui/interface.ts` は HUD、会話、外見設定。
- `world/`: ワールド配置、障害物、環境素材。

町の中心は提供画像 `public/assets/town-reference.jpg` です。拡張部分には画像の一部を繰り返した `public/assets/town-expanded.jpg` を使用しています。元画像に対応した簡易衝突領域を `world/Town.ts` で各地区に展開します。画像中の人物、UI、建物は背景に焼き込まれているため操作できず、プレイヤーはそれらの手前に描画されます。拡張地区では建物や人物が繰り返され、画像の継ぎ目も見えます。衝突領域は概略で、細部には一致しません。公開する前に、提供画像を配布する権利をご確認ください。

中央広場の一部には `world/CentralSquare.ts` の独立した床・装飾・噴水を重ねています。床と噴水はオリジナルの軽量な WebP 素材で、元の噴水は床で覆っています。中央の噴水は複数の矩形で角を切った当たり判定を使い、プレイヤーとモンスターで同じ地形データを参照します。建物・画像内の人物や UI は元の背景に焼き込まれたままで、別レイヤー化や通行判定の細かな調整は今後必要です。

## 現在の制限と次回

会話は固定文で、NPC 同士やプレイヤーとの衝突、経路探索、会話中の NPC 停止はありません。遠距離 NPC・モンスターの思考頻度の間引きは未実装です。ピンチズーム、建物内部、クエストはありません。

### 採取・製作の基礎

`crafting/data.ts` に5種類の採取地点と鍛冶・裁縫・大工・料理の4レシピを定義し、`CraftingEngine` は採取距離、共有の再使用時間、素材の消費、製作者名と種別ごとの経験回数を管理します。`CraftingManager` と `CraftingUI` は地点と画面を担当します。オンラインでは Worker が採取・製作を判定し、地点の状態を同室へ同期します。バッグの空きや材料が不足する場合は、材料を消費しません。オフラインではローカルで同じ処理を行います。

製作時の品質は職種ごとの製作成功回数と乱数で決まり、経験を積むと高品質の確率が上がります。装備の品質補正は Poor 0.8倍、Normal 1倍、Fine 1.2倍、Exceptional 1.4倍、Masterwork 1.6倍で、各能力値を整数に丸めます。耐久が0の装備は補正が無効です。消耗品にも品質は記録されますが、回復量は変わりません。

現状は初期プロトタイプで、道具の必須化、作業台、製作時間は未実装です。オンラインの経験・地点・持ち物はメモリ上のみで永続化されず、実 Worker での複数端末の検証も未完了です。`node tests/crafting.cjs` で基礎ロジックを検証できます。

### 取引掲示板の試作

`market/MarketEngine.ts` はサーバー上で出品物を預かり、購入時に代金と品物を一度に移動します。持ち物・価格・硬貨残高・両者のバッグ容量を検査し、失敗時は双方を元に戻します。同じ出品の購入は先着1人です。出品は1人5件まで、価格は1〜500硬貨で、出品物はキャンセルまたは購入までバッグから外れます。通貨・取引履歴・出品物は永続化されず、Worker の再起動で消えます。ID は認証されておらず、これは信頼できる経済システムではなく開発用の試作です。オフライン取引や本格的な店舗・オークションはありません。ローカルの実 Worker で2接続による取引を検証しましたが、公開環境や2台の実端末では未検証です。`node tests/market.cjs` で売買とロールバックを検証できます。

### アイテム・装備

`items/items.ts` は名前・カテゴリ・重量・最大スタック・レア度・装備スロット・補正などの定義、`items/model.ts` は品質・耐久などを持つ実体、バッグ、装備、地面アイテムの型です。`dropTables.ts` は敵ごとの確率と個数を管理し、`ItemEngine` は取得、スタック、装備、解除、消費、破棄、重量、耐久と最終ステータスを扱います。`ItemManager`、`GroundItemManager`、`ItemUI` は表示と入力を担当します。アイコンは `ItemAssetRegistry` で生成し、キャラクター描画の上に武器・盾・胴・頭の簡易レイヤーを重ねます。

オンラインでは Worker の `ItemEngine` がドロップ抽選、地面の所有状態、取得距離、空き容量、装備・使用を判定し、`ITEM_ACTION` に対して持ち物を本人に、地面と装備表示を同室に配信します。同じアイテムの取得は先着1人のみです。攻撃力・魔力・防御力・攻撃速度と耐久は Worker 側の戦闘判定に反映されます。HP / MP 回復アイテムには使用間隔があります。重量が上限を超えると移動速度が下がり、武器・防具の耐久が0になると補正が無効になります。通常の地面アイテムは3分で消えます。

初期バッグには動作確認用の武器、布、盾、薬を入れています。オフラインのバッグ・装備・製作経験と期限内の地面アイテムは、ブラウザの LocalStorage にプレイヤー ID ごとに保存します。オンラインの状態とは共有せず、オンラインでは Worker の状態を使います。保存不可・破損時はコンソールや画面に警告し、不正な既存データは上書きしません。セーブの消去はブラウザのサイトデータ削除で行えます。採取地点の再使用時間、HP、位置、オフラインの敵状態は保存しません。同一ブラウザの複数タブで同じ ID を同時操作すると保存が競合するため避けてください。

オンラインのバッグは Worker のメモリのみで、ルーム再起動時に初期化されます。ID は認証されないため、本番の所有権保護・永続化は未完成です。装備表示は簡易レイヤーです。旧キャラクター素材の職業別の持ち物も焼き込まれています。スタック分割、ドラッグ操作、修理は未実装です。`npm run test:items` と `node tests/persistence.cjs` で基礎ロジックを検証できます。

### 戦闘

`combat/model.ts` に敵の定義、攻撃値、安全地帯と状態、`CombatEngine.ts` に衝突・5Hz の AI・攻撃判定・死亡・復活をまとめています。`CombatManager` は選択と要求、`MonsterManager` は表示、`ProjectileManager` は飛翔物とダメージ演出を担当します。オンライン時、Worker の部屋が共通の敵 HP とプレイヤー HP / MP を保持し、攻撃要求から距離・クールダウン・MP とダメージを判定します。200ms ごとに状態を配信します。オフライン時は同じエンジンのローカル版で遊べますが、再接続時にサーバー状態へ切り替わり、戦闘状態は引き継がれません。

モンスターは簡易の衝突矩形を使い、遮蔽物に詰まると帰還します。経路探索や攻撃の遮蔽物判定はありません。攻撃アニメーションは色変化と簡易エフェクト、死体は復活まで半透明表示です。復活・敵の状態はメモリ上のみで、ルームが再起動すると初期化されます。プレイヤー位置は従来どおりクライアント由来で、攻撃可能距離の検証は完全な不正対策ではありません。PvP はありません。`npm run test:combat` で戦闘ロジックを検証できます。

### オンライン同期の開発

1. Node.js と npm を用意し、`npm install` を実行します。
2. `.env.example` を `.env.local` にコピーし、`VITE_WS_URL=ws://127.0.0.1:8787` を設定します。
3. 別々の端末で `npm run worker:dev` と `npm run dev` を実行します。Vite と Worker を両方起動し、表示された Vite の URL を2つの別ブラウザプロファイルで開きます。別の実機から接続する場合は、その端末から到達できる Worker のアドレスを指定し、必要に応じて Worker の listen アドレスを変更してください。HTTPS 配信の場合は `wss://` が必要です。
4. `npm run test:network` は Worker の実際のメッセージ処理を WebSocketPair のテスト用代替で検証します。死亡状態をテスト用に設定してからの再接続と復活も検証しますが、workerd やブラウザでの死亡操作を再現するものではありません。`npm run worker:check` は型チェック、`npm run worker:build` は公開しないビルドです。

Worker をローカルで起動した後は `npm run worker:smoke` で、`127.0.0.1:8787` の WebSocket 接続と入室応答を確認できます。このチェックは公開先へ接続せず、短時間だけ確認用プレイヤーを入室させます。接続できない場合は `npm run worker:dev` が「Ready」まで進んでいるか確認してください。

さらに `npm run worker:two` で隔離された一時ルームに2接続し、移動、チャット、敵の討伐、硬貨取得、装備・出品後の再接続、購入、退出を順番に確認できます。これはローカル Worker 専用で、本番サーバーには接続しません。再接続時の復元はルームのメモリが維持されている間に限られ、Worker の再起動をまたぐ保存ではありません。

`npm run worker:death` はローカル Worker の隔離ルームで、モンスターによる死亡、死亡中の再接続、復活地点への移動と HP 回復を確認します。完了まで20秒程度かかります。ブラウザ画面での操作確認は含みません。

ブラウザからの通信を検証用に変更して狼の近くに入室させた確認では、死亡と復活時にゲーム画面向けの HP・死亡状態の通知が発生しました。通常操作で現地に移動してから死亡・再接続する確認は残っています。

2026年10月30日、ローカルの Wrangler / workerd で `worker:smoke` と `worker:two` を確認しました。さらに同一 PC 上の独立した2つのブラウザで、Online 表示、他プレイヤー情報の受信、移動の送受信、チャット表示、切断通知と自動再接続後の再入室を確認しました。2台の実端末や公開先での確認は含みません。実行環境によってはローカルポートへの接続が制限されることがあります。

### Cloudflare と GitHub Pages

Cloudflare アカウントで `npx wrangler login` し、`npx wrangler deploy --config worker/wrangler.toml` を実行すると Durable Object と Worker をデプロイできます。`workers.dev` の URL を `wss://` にした値を Vite のビルド環境変数 `VITE_WS_URL` に設定し、ゲームディレクトリで `npm ci` と `npm run build` を実行して `dist/` を Pages に配置します。接続先はビルド時に埋め込まれる公開 URL で、秘密情報を指定しないでください。現リポジトリの既存 Pages ワークフローは株アプリを公開するため、ゲーム向けにビルド・配置するステップを別途追加するか、別リポジトリで公開してください。

### 同期方式と制限

`NetworkManager` は同時接続を1本に保ち、JOIN に対するプレイヤー一覧を受信してから Online と表示します。10秒以内に入室応答がなければ接続を閉じて再試行します。入室後は状態が変わった場合のみ最大10回/秒で位置・向き・移動状態を送ります。外見と名前は JOIN または変更時に送ります。切断時は他プレイヤー表示を消し、1、2、4、8秒と再接続間隔を伸ばし最大30秒に制限します。復帰時は現在状態を再送します。10秒ごとの PING に対し30秒応答がない接続を閉じ、Worker は45秒無通信の接続を掃除します。`RemotePlayerManager` は受信時刻の履歴を120ms遅らせて補間し、表示対象の管理を担当します。`node tests/network-state.cjs` は接続状態と JOIN 応答を模擬検証します。

同じルームのメモリが残っている間は、切断時の HP・MP・死亡時間・攻撃クールダウンも保持し、再入室時に復元します。切断中のプレイヤーはモンスターの攻撃対象にはなりません。Worker の再起動をまたぐ永続化や認証は未実装です。

Worker は `town_01` 等のルームごとに Durable Object を分け、入力の型・座標範囲・移動距離・発言長と送信間隔を検査します。ただし ID は認証されず、偽装・なりすましを防げません。プレイヤーの地形衝突はサーバーで検証しておらず、本格的なチート対策は未実装です。同じブラウザのタブは ID を共有し、後の接続が先の接続を置き換えます。サーバー再起動時の状態・チャットの永続化、NPC 同期、認証はありません。URL 未設定時や接続失敗時は Offline としてローカル操作を続けられます。
