# Ashenvale — 灰樹の町

真上に近い視点の Phaser 3 / TypeScript / Vite 製2DファンタジーRPGです。探索、NPC会話、戦闘、戦利品、装備、採取・製作の試作を遊べます。

公開ゲーム： https://mametank51-rgb.github.io/stock-edge-intelligence/fantasy-town/

**公開版は現在 Offline モードです。** ローカルの Cloudflare Worker では複数人の同期を確認済みですが、公開 Worker と接続先の設定は未完了です。2026-11-01 の確認で Wrangler は未ログインでした。アカウント認証や本番の経済・保存基盤が完成したMMORPGではありません。

## 起動・検証

Node.js と npm を用意して、ゲームのディレクトリで実行します。

```sh
npm install
npm run dev
npm run build
npm test
npm run worker:check
npm run worker:build
```

`npm test` は通信、補間、戦闘、アイテム、採取・製作、取引、保存、通行経路、外見と操作判定の10スイートを実行します。保存テストで出る破損データの警告は、上書き防止を意図的に検査したものです。ビルド時の大きなチャンクの警告は Phaser を含むバンドルに対するもので、ビルドエラーではありません。

## 保存とバックアップ

オフラインのバッグ・装備・製作経験・期限内の地面アイテムはプレイヤーIDごとに LocalStorage に保存します。名前と外見も保存します。HP、位置、敵状態、採取地点の待ち時間は保存しません。同じブラウザの複数タブで同じ記録を操作することは避けてください。

「設定・操作案内」から JSON の記録を書き出し、読み込めます。対象はオフラインの持ち物・装備・経験・地面の品物だけです。形式、種類、数量、スロット、重複ID、重量、期限を検証し、確認後に置き換えて再読み込みします。別ブラウザのバックアップも現在の端末IDへ移せます。オンラインの所有物へは持ち込めません。壊れた既存セーブは自動で上書きしません。

オンラインの持ち物・製作経験・出品物は Worker のメモリのみです。同じルームが維持されている間の再接続では復元されますが、Worker の再起動をまたぐ保存はありません。

## オンライン開発

1. `.env.example` を `.env.local` へコピーし、`VITE_WS_URL=ws://127.0.0.1:8787` を設定します。
2. 別々のターミナルで `npm run worker:dev` と `npm run dev` を実行します。
3. 異なるブラウザプロファイルで Vite のURLを開きます。同じブラウザのタブはIDを共有し、後から接続したタブが先の接続を置き換えます。
4. Worker 起動後、`npm run worker:smoke`、`npm run worker:two`、`npm run worker:death` で実 workerd の接続、2接続の同期・売買、死亡中の再接続と復活を確認できます。

`NetworkManager` は1本の接続を管理し、JOIN応答後に Online と表示します。移動変更は最大10Hz、低頻度のプロフィール・装備は変更時、戦闘状態は5Hzで送ります。RemotePlayer は120msの受信バッファで補間します。再接続は1、2、4、8秒…最大30秒、入室応答待ちは10秒。10秒ごとにPING、30秒応答なしで再接続し、Worker は45秒無通信の接続を掃除します。

Worker がアイテム取得競合、装備、ドロップ、戦闘距離、クールダウン、HP・MP、死亡・復活、取引を判定します。IDに本格認証はなく、プレイヤー地形衝突はサーバーで検査していません。本番向けの不正対策ではありません。オフラインとオンラインの所有物は別管理です。

## 公開

このリポジトリの `.github/workflows/pages.yml` は株アプリの配信を保ち、ゲームを `fantasy-town/` サブディレクトリへビルドして配置します。Vite の `base: './'` を維持しています。

公開オンライン接続を有効にする場合：

```sh
npx wrangler login
npx wrangler deploy --config worker/wrangler.toml
```

取得した Worker のURLを `wss://` にした値を、GitHubリポジトリの Actions 変数 `FANTASY_TOWN_WS_URL` に設定して Pages を再デプロイします。ワークフローが `VITE_WS_URL` としてビルドへ渡します。直接ビルドする場合は `VITE_WS_URL` を設定してください。フロントエンドへ秘密鍵・APIトークンを入れません。

## 描画と素材

操作可能な人物の標準 Human Warrior / Mage / Archer と一部NPCにはオリジナルの16bit風素材を使用します。他の外見はコード生成の仮フレームです。`CharacterAssetRegistry` で方向・動作を管理し、`equipmentArt.ts` の武器・盾・鎧・頭のレイヤーをワールドと装備画面で共用します。元の人物画像に焼き込まれた衣服や持ち物まで完全に脱着できる方式ではありません。

キャラクター画像は32 × 40のフレームに事前整理し、読込対象を12,521,798 bytesから284,712 bytesへ削減しました。元画像は `art/characters/` に残し、公開用は `public/assets/characters/` に配置します。元の描画との176フレーム比較を行っています。通常のビルドで画像を再生成する必要はありません。

任意の画像再生成・ブラウザ検証には Playwright と Chrome が必要です。`npm install --no-save --package-lock=false playwright` などで Playwright を用意し、`npm run art:pack`、`npm run test:art`、ゲーム起動後に `npm run test:browser` を実行します。外部配置の Playwright は `PLAYWRIGHT_MODULE` にモジュールパスを指定できます。ブラウザテストの既定接続先は `http://127.0.0.1:5178` で、`GAME_URL` により変更できます。確認画像は `evidence/` へ出力します。

背景は提供画像を基にした `town-expanded.jpg` で、元画像は `art/town-reference.jpg` に保管しています。背景内の人物、家具、UIは動かせない画像の一部です。建物を隠す・内部に入る・画像内の物を調べる機能はありません。拡張部分に繰り返しと継ぎ目があり、衝突も概略です。中央の床・噴水だけは独立した描画を重ねています。

## 主要構造と残る課題

`src/game/` の `state`、`characters`、`entities`、`npc`、`world`、`input`、`combat`、`items`、`crafting`、`market`、`network`、`persistence`、`ui` に責務を分けています。`worker/src/index.ts` の Durable Object は共有エンジンを使用します。
